# 「生成AIっぽさ」を消すためのチェックリストとBefore/After

このファイルは実際の運用で「生成AIっぽさが残ってる」「見出しが胡散臭い」と2回
指摘され、修正した実例から作った。**style_guide.mdの他のルールを守っていても
これらの癖が出ると「AIが書いた」とバレる。** 下書きができたら必ずこの一覧で
セルフチェックすること。

## 1. 見出しが「レポート的な番号立て」になっていないか

生成AIは構造化しようとして、見出しを実験レポートのように細かく分割しがちになる。
この著者はそこまで律儀に構造化しない。

- ❌ 悪い例：「### 原因調査」「### 1回目の修正（これも失敗）」「### 2回目の修正（正攻法）」
- ✅ 良い例：大ぶりなH2を2〜3個並べるだけにする。上記の中身は全部
  「## やってみた」1つの下に、地の文の流れで書く（見出しで区切らず、
  「〜と思って直しました」「これもダメで」のように文章の接続で進行を示す）。

## 2. 見出しで「釣ろう」としていないか（胡散臭さの正体）

- ❌ 悪い例：「`--temporary`、ほんとにあった」「なぜかカウントダウンが『もう消滅した』表示になる」
  → クリックベイト的な煽り、ドラマチックな引き（「ほんとに」「なぜか」で興味を煽る書き方）は
  この著者はやらない。
- ✅ 良い例：実例集（`examples/`）の見出しを見ると「useChatの仕様が公開されている」
  「AgentCore SDKを使うともうちょっと簡単に」のように、**素っ気ない事実の言い切り**になっている。
  ドラマチックに煽らず、淡々と「何をした・何がわかった」を述べるだけでいい。
- 実際の見出し構成の型（この著者らしい大ぶりな分割）：
  ```
  ## 環境
  ## やってみた
  ### （必要なら中身をサブ見出しで軽く区切る程度）
  ## 動作確認
  ## まとめ
  ## 参考
  ```

## 3. ヘッジ表現を「均質に」連発していないか

style_guideは「断定を避けるヘッジ表現を混ぜる」と言っているが、**これを毎文につけると
逆に不自然な「AIっぽさ」になる**。ヘッジは味付けであって、主食ではない。

- ❌ 悪い例：「〜のようです」「〜らしいです」「〜のようです」と同じ言い回しを何度も繰り返す
- ✅ 良い例：ヘッジ表現は1記事に数箇所程度に抑え、代わりに以下でリズムを崩す：
  - 体言止め・短い断定：「0。」「毎回違う。。」「まだ固定されない。」
  - 「。。」「w」で余韻・脱力を出す
  - 淡々とした言い切り（「〜でした」で終わらせる。無理に推測に変えない）

## 4. 太字で結論を強調しすぎていないか

- ❌ 悪い例：`**0が返ってきていました。**`のように、結論部分をいちいち太字にする
- ✅ 良い例：太字を使わず地の文に溶かす。「0。」のように短く言い切るだけで十分目立つ。
  太字はこの著者も使うが（`**AIエージェントをどう構築するか**」など）、
  「結論を毎回太字で強調する」ような機械的な使い方はしない。

## 5. 説明口調の因果接続になっていないか

- ❌ 悪い例：「原因は〇〇でした。△△だったからです。」
  「〇〇が発生しました。これは△△という理由によるものです。」のような、
  教科書やレポートのような因果の説明構文
- ✅ 良い例：因果を律儀に接続詞でつながず、もっと直接的に言い切る。
  「Cloudflare Workersは、モジュールのトップレベルで動くコードだと、Spectre対策で
  `Date.now()`が常に0を返すみたいです。」のように、原因をそのまま地の文で言うだけでいい。
  「〜が原因です」「〜だからです」という定型句を避ける。

## 6. 「まとめ」が教科書的な箇条書きになっていないか

- ❌ 悪い例：
  ```
  ## まとめ
  - Aができました
  - Bという挙動がありました
  - Cが重要な学びでした
  ```
  （3点セットで律儀に総括する、レポートのような箇条書き）
- ✅ 良い例：箇条書きにせず、力の抜けた2〜3文に圧縮する。
  「ログインなしで、ほんとにデプロイできました。〜が今回いちばんの収穫でした。」
  のように、感想として流れるように書く。箇条書きの「まとめ」がこの著者に無いわけでは
  ないが、多用すると機械的に見える。文章で流す方を基本にする。

## 総合チェックリスト（下書き後に必ず確認）

- [ ] 見出しが実験レポートのように細分化・番号立てされていないか
- [ ] 見出しが「ほんとに」「なぜか」のような煽り・クリックベイト的な言葉を使っていないか
- [ ] 同じヘッジ表現（〜のようです等）を3回以上連発していないか
- [ ] 太字が「結論を毎回強調する」ための機械的な用途になっていないか
- [ ] 「〜が原因です」「〜だからです」という説明口調の因果接続を使っていないか
- [ ] 「まとめ」が3点セットの教科書的箇条書きになっていないか（文章で流せているか）
